# 平台联调验收口径

本轮验收只认这一套口径：

- Web 后端：`http://127.0.0.1:8000`
- TCP 入口：`127.0.0.1:9100`
- Web 前端：`http://127.0.0.1:5173`
- ACK 策略：平台解析并入库成功时，必须返回 HJ212 `CN=9014`、`ST=91`、`Flag=8` 的 ACK 报文
- PC 判据：PC 端必须收到并校验合法 `9014 ACK`，才能判定本次协议发送成功
- PC ACK 等待建议：默认 `3s`，最低不建议低于 `1s`；`0.2s` 容易误判平台慢响应为 ACK 缺失

`127.0.0.1:8998` 仅是旧 PC 工程历史默认端口，不作为本轮正式验收口径。

## 旧库兼容点

平台启动时会执行 `ensure_database_schema()`：

- 干净新库：创建完整表结构
- 旧库：如果 `protocol_upload_logs` 缺少 `data_time` 字段，自动补 `data_time DATETIME NULL`
- Web 后端和 TCP 接收端都会执行该确认逻辑

这个兼容点只补缺失字段，不删除表、不清数据、不改变已有字段。

## 固定失败报文

```text
##0012QN=1;CN=2011FFFF\r\n
```

预期：平台应返回协议失败结果或记录 `rejected`，不得把该包判定为成功验收。

## 页面验收证据

总览页“联调状态看板”应显示：

- 最近设备：`A110000_0001`
- 最近接收状态：`accepted`
- 最近接收结果：`TCP accepted and stored`
- ACK 状态：`ACK 正常（已收到 CN=9014）`
- ACK 包摘要：`平台已返回 CN=9014 ACK`

说明：后端接口仍可保留 `valid_9014_ack`、`missing_ack`、`not_applicable` 等机器值，页面展示层必须转换成人可读中文。

截图与证据采集清单见 [最终验收截图证据清单.md](./最终验收截图证据清单.md)。

协议接收日志应显示：

- `source=tcp`
- `CN=2011` 或 `CN=2061`
- `status=accepted`
- `metricCount=5`
- `ackPacket` 包含 `CN=9014`

实时监测应显示：

- `w01010`
- `w01014`
- `w01001`
- `w01017`
- `w01019`

## 失败排查顺序

1. 没有新日志：确认 PC 是否发到 `127.0.0.1:9100`
2. 没有合法 `9014 ACK`：确认是否命中当前仓库 TCP 服务
3. `status=rejected`：检查报文长度、CRC、CP 段和 `DataTime`
4. `status=ingest_failed`：检查数据库连接和表结构
5. ACK 合法但页面没更新：检查 Web 后端和前端是否运行在当前仓库
