# 需求变更 QA 测试计划

## 回归优先级

P0 必须先过：
- PC 同一轮采集不得重复发包：同一轮自动采集产生的新 `UploadTask` 只能上传一次，成功后状态必须变为 `uploaded`，不得再次被 pending 队列发送。
- PC 实时保存默认间隔必须为 `30 秒`：新装、无历史配置、清空配置后三种场景均应显示并使用 `30 秒`。
- 平台数据库查询必须可查历史：`CN=2011` 实时数据、`CN=2061` 小时数据、协议日志均必须从数据库查到，不得只依赖内存或页面缓存。
- 北京时间必须正确：报文 `DataTime` 表示设备数据时间，平台 `receivedAt` 表示平台接收时间，返回值应带 `+08:00`，两者语义不得混淆。

P1 变更功能：
- 数据质量规则：正常、超标、疑似离群、疑似恒值、缺失/异常。
- 告警记录与通知预留：触发告警时必须有告警记录，短信未配置不得阻塞采集、入库、查询主流程。
- 平台/PC 数据分析页：趋势图有数据，空数据有提示，阈值和建议可解释。

P2 展示完善：
- 分析建议文案主依据必须引用本项目标准目录 `D:\pamGo\工程项目\ZEUSS_DIR国家水站项目\文档\地表水技术要求\` 下的地表水技术要求附件；`GB 3838-2002 地表水环境质量标准` 仅作为背景参考，不得替代项目附件口径。
- 建议不得写成医疗、生产或设备故障的绝对结论，只能作为现场判断参考。

## 建议新增自动化用例

- PC 重复发包：mock 平台 TCP ACK，执行一次 `auto_collect_all_devices` 或 `auto_collect_selected_devices`，断言同一批 `task_ids` 只调用一次上传客户端，二次执行不得重发已 `uploaded` 任务。
- PC 默认 30 秒：清空 `SystemSetting` 后调用 `get_runtime_settings`，断言 `save_interval_seconds == 30`；保存为其他值后重启服务仍按用户配置展示。
- 数据质量规则：用同一设备构造正常值、超过阈值、明显跳变、连续 N 次同值、缺失/非法值，断言查询页和分析页的质量标签一致。
- 标准来源检查：页面、接口、导出字段中的标准来源必须引用本项目地表水技术要求目录及对应附件；若出现 `GB 3838-2002`，只能作为背景参考，不能替代附件依据；若出现 `GB 11607-1989`，不能作为主依据。
- 附件 5/6 核对：`CN=2011`、`CN=2061`、`DataTime`、接收时间、数据标记、协议日志持久化字段、质量判断字段必须回到附件 5/6 的表格和字段定义核对。
- 指标优先级：第一批优先覆盖水温、pH、溶解氧、电导率、浊度；第二批预留 CODMn、氨氮、总磷、总氮。
- 告警记录：超标值入库后必须生成告警记录；短信未配置时告警记录仍生成，主流程返回成功或可解释的非阻塞状态。
- 通知频率限制：同一设备同一指标在限制窗口内多次超标，只允许一次短信发送尝试；测试发送接口必须返回成功/失败原因和时间戳。

## 时间问题复测方法

1. 向平台发送固定北京时间报文：`CN=2011`，`DataTime=20260706103000`。
2. 打开协议日志页，按 `CN=2011` 和固定 `MN` 查询。
3. 核对 `数据时间` 为 `2026-07-06 10:30:00` 语义，不应被换算成 UTC。
4. 核对 `接收时间` 是平台收到报文的当前北京时间，API/JSON 中应带 `+08:00`。
5. 若 `接收时间` 与现场当前北京时间相差超过 5 分钟，且非人为回放历史数据，应判为时间口径风险。

## 数据质量规则红线

- 阈值不可配置，或页面展示与后端查询结果不一致，不建议通过。
- 页面、接口或文档只写 `GB 3838-2002` 或 `GB 11607-1989`，但没有引用本项目地表水技术要求目录及对应附件，不建议通过。
- 页面或接口仍把 `GB 11607-1989` 写成阈值/超标/分析建议的主依据，不建议通过。
- 阈值、质量判断或分析建议来源未标明本项目地表水技术要求附件或项目可配置来源，不建议通过。
- `CN=2011`、`CN=2061`、`DataTime`、接收时间、数据标记、日志持久化、质量判断未按附件 5/6 人工核读确认，不建议进入最终签字。
- 超标数据没有质量标签或告警记录，不建议通过。
- 离群、恒值第一版只能标记为“疑似离群”“疑似恒值”，不得直接写成“设备故障”“水质必然异常”。
- 分析建议写成不可配置、不可解释或绝对诊断结论，不建议通过。
- 缺失值、非法值、单位缺失不能导致页面崩溃，也不能被展示为正常数据。

## 短信预留测试红线

- 短信未配置导致采集、协议入库、数据查询失败，不建议通过。
- 没有告警记录，仅尝试短信发送，不建议通过。
- 没有频率限制，导致同一告警连续刷短信，不建议通过。
- 测试发送接口不能返回发送结果、失败原因或时间戳，不建议通过。

## 分析页验收用例

- 有数据：趋势图展示最近数据点，指标名称、单位、时间轴清楚。
- 空数据：显示“暂无数据/请先采集或查询”的友好提示，不出现空白图或报错。
- 超标：趋势点、表格、建议区同时能解释触发阈值、实际值、阈值来源，主依据显示为本项目地表水技术要求目录及对应附件；`GB 3838-2002` 只能显示为背景参考。
- 指标覆盖：水温、pH、溶解氧、电导率、浊度必须有质量规则展示；CODMn、氨氮、总磷、总氮至少预留字段、配置位或后续扩展口径。
- 疑似离群：只提示“疑似”，说明可能原因包括传感器波动、现场扰动、采集异常，要求复核。
- 疑似恒值：只提示“疑似”，说明可能原因包括水体稳定、传感器卡死、采集链路异常，要求结合现场。
